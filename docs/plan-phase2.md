- 1ファイルだけ選ばれた場合は従来どおりの単票画面に流す

### P2-C: VBA ソース抽出と静的解析

#### 伸長 — **動作確認済み（2026-08-16）**

[../src/worker/ovba.ts](../src/worker/ovba.ts) に MS-OVBA の伸長を実装した。**Excel が実際に書き出したファイルから、ソースをバイト単位で正確に復元できることを確認済み**（テスト8件・[../tests/worker/ovba.test.ts](../tests/worker/ovba.test.ts)）。

復元例:

```vb
Attribute VB_Name = "Module1"
Sub SampleMacro()
    MsgBox "確認用"
End Sub
```

文字列リテラルは cp932 の `8a 6d 94 46 97 70`（確認用）で一致した。**1バイトでもずれれば一致しないので、これが実装の正しさの裏づけになる。**

実装上の要点:

- 圧縮チャンクのコピートークンは、**そのチャンク内で既に展開したバイト数によってビット幅が変わる**（4〜12ビット）。ここを固定幅で実装すると、短いモジュールだけ通って長いモジュールで壊れる
- コピー元とコピー先が重なることがあるため、まとめてコピーせず1バイトずつ写す
- **ソースの開始位置は `dir` の MODULEOFFSET に書かれているが、`dir` の解析は避けた。** レコード内に Unicode 名が入れ子で続く箇所があり、素直な走査では位置がずれるため。代わりに「コンテナらしき位置を探して伸長し、結果が `Attribute VB_Name` で始まるかを検証する」方式を採った
- **この検証は実際に機能している。** 実ファイルのモジュールストリームには、コンテナに見えるが伸長すると2バイトしか出ない偽の候補が存在した（テストで固定済み）

#### 静的解析 — **完了（2026-08-16）**

6ルールを新設した（[../src/rules/vba-code.ts](../src/rules/vba-code.ts)）。重大度は開発者承認済み。

| ルール | 重大度 | 検出内容 |
|---|---|---|
| `VBA_NETWORK_ACCESS` | RED | 外部への通信（XMLHTTP / WinHttp など） |
| `VBA_SHELL_EXEC` | RED | シェル・外部プログラムの実行 |

**★ Finding には件数と類型しか載せない。** 該当行の内容・行番号・モジュール名も出さない。解析層（[../src/worker/vba.ts](../src/worker/vba.ts)）がそもそも件数しか返さない設計なので、ルール側で漏らしようがない。

**コメントは判定から除く。** コメントアウトされたコードを「実行される」と誤検知しないため。VBA のコメントは `'`（文字列の外）と行頭の `Rem`。

#### フィクスチャの作り方

検出ルールにはフィクスチャが要るが、Excel を使わずに VBA 入りの `.xlsm` を作る必要がある。**MS-OVBA の非圧縮チャンク**（仕様上正当な形式）でコンテナを組むことで、**自作の圧縮器を持たずに**実現した（[../fixtures/vba-builder.ts](../fixtures/vba-builder.ts)）。自作の圧縮器で作ったデータを自作の伸長器で読むと検証にならないため、あえて持たない判断。

**★ 手続き名は、レポートの文言に出てくる普通の日本語と衝突しない語にすること。** 当初 `Sub 起動する()` `Sub 取り込む()` としたところ、漏洩テストが自分の文言（「…を起動する記述が」「…を取り込む記述が」）に反応して誤検知した。テストが意味を失うので避ける。

#### ★ 実ファイルから分かったこと（参考）

`dir` ストリームには、**そのファイルを編集した端末のローカルパスが埋め込まれている**。今回のサンプルにも `/Users/<利用者名>/Library/Containers/com.microsoft.Excel/...` が入っていた。

- **フィクスチャの扱い:** [../fixtures/vba/sample-macro.xlsm](../fixtures/vba/sample-macro.xlsm) にも開発者のホームディレクトリ名が含まれている。プライベートリポジトリなので実害は小さいが、公開する場合は差し替えが必要
- **製品としての観点:** 顧客のマクロ入りブックにも同様に作成者の端末パスが残っている。検出項目として扱う価値があるかもしれない（未検討）

**★ 検証用の本物ファイルは用意済み。** [../fixtures/vba/sample-macro.xlsm](../fixtures/vba/sample-macro.xlsm) を検証オラクルにする。自作の圧縮器で作ったデータを自作の伸長器で読んでも、自分のバグは見つけられない。

伸長できたら、期待値は `Sub SampleMacro()` / `MsgBox` を含むソースになるはず（可読断片から推測）。ここが一致すれば伸長が正しいことの裏づけになる。

**★ C-4 / §7-2 の新しい論点。** VBA ソースは顧客の業務ロジックそのもので、数式以上に機微。Finding には「外部への通信を行うコードが含まれています（3箇所）」のように**件数と類型のみ**を出し、ソース断片は一切出さない。数式に対する扱い（[plan-phase1.md](plan-phase1.md) の M3）と同じ規律を適用する。
